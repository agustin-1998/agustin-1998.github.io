From user story to merge-ready branch, with a human at every checkpoint.

hu-flow is a workflow of 12 Claude Code agents for day-to-day product work. It reads an Azure DevOps user story, asks what is missing, plans, writes the code and the tests, verifies every acceptance criterion in a real browser or against the API, and runs code, security and vulnerability reviews. The developer approves every checkpoint and nothing is pushed without their word.

Guardrails, not good intentions

  • Hooks check every command before it runs. Merges, rebases, force pushes, files outside the approved plan and traffic outside localhost are blocked.
  • Nothing is pushed until the developer types push.
  • Agents never touch git or publish anything; the session does, with approval.

Verified before it says “done”

  • Every acceptance criterion and every Figma flow is checked on the final code, measured to ±1 px.
  • APIs get real calls to every endpoint, including without a session and with a role that should be denied.
  • If anything changes after that, the whole pass runs again.

Measured, not guessed

  • Used on 4 user stories and 5 bug fixes in production work.
  • A token-cost analysis of 6,776 model calls showed that 64% of the spend was re-sent context, which led to shorter verification batches.
  • The code is private; this page shows how it works.
